# 安装与运行

## 1. 准备环境

- Node.js 22 或更高版本及其附带的 npm。本项目本次构建和模拟回归测试使用 Node.js 24。
- Git（用于克隆和更新代码）。
- 可访问模型服务的网络，以及 DeepSeek、OpenAI、Gemini 中至少一个可用 API key。
- Google TTS key 为可选项；只运行文字对话不需要。

不需要 Python 或 Conda。项目包含两个独立的 Node.js 项目，依赖清单及锁定版本分别位于 `client/package.json`、`client/package-lock.json` 和 `server/package.json`、`server/package-lock.json`。无需再维护手写依赖版本列表。

在 PowerShell 中检查：

```powershell
node --version
npm --version
git --version
```

如果提示无法识别 `node`，请安装 Node.js 并重新打开终端，确认其安装目录已加入 PATH。若 PowerShell 阻止执行 `npm.ps1`，可用 `npm.cmd` 代替下文中的 `npm`，无需为此修改全局执行策略。

## 2. 下载与安装依赖（首次运行）

仓库地址保留维护者创建时的拼写 `DiaglogLab-Chinese`，与界面名称不同。

```powershell
git clone https://github.com/upczss/DiaglogLab-Chinese.git
cd DiaglogLab-Chinese
cd server
npm ci
cd ../client
npm ci
cd ..
```

`npm ci` 按仓库锁文件安装依赖，需要网络。以后更新代码且锁文件发生变化时，再在对应目录运行一次。

## 3. 配置后端

在仓库根目录执行，仅首次复制：

```powershell
Copy-Item server/.env.example server/.env
```

用编辑器打开 `server/.env`。例如使用 DeepSeek：

```dotenv
NODE_ENV=development
PORT=3010
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=在本地填写自己的密钥
GEMINI_API_KEY=
OPENAI_API_KEY=
TTS_API_KEY=
```

使用 Gemini 时设置 `LLM_PROVIDER=gemini` 并填写 `GEMINI_API_KEY`；使用 OpenAI 时设置 `LLM_PROVIDER=openai` 并填写 `OPENAI_API_KEY`。

也可以通过网页「密钥设置」配置模型服务。网页密钥会保存在当前浏览器的 localStorage，并发送给后端用于调用服务。重启后端后，若只通过网页配置过密钥，可能需要再次打开密钥设置并保存。界面仍提示配置时，请选择与后端一致的服务商。

`.env` 仅留在本机，已被 Git 忽略；`.env.example` 只包含空值。不要把真实密钥写入前端源码或任何 `VITE_` 环境变量，这类变量会进入浏览器构建结果。

`NODE_ENV=development` 用于生成本地音频及素材地址。默认前端地址和 CORS 使用 5173，后端地址使用 3010；首次使用建议保持这些端口。

## 4. 每次打开项目

打开两个 PowerShell 窗口，分别进入你保存仓库的位置。下文假设窗口均从仓库根目录开始。

**窗口一：启动后端**

```powershell
cd server
npm start
```

后端监听 <http://localhost:3010>。浏览器直接访问根地址不一定有页面，这是 API 服务。

**窗口二：启动前端**

```powershell
cd client
npm run dev -- --host localhost --port 5173 --strictPort
```

打开 <http://localhost:5173>。两个终端均需保持运行。只打开网页或只启动前端，无法生成对话和保存服务端密钥。

## 5. 首次使用

1. 在「密钥设置」选择模型服务并保存。Google 语音密钥选填。
2. 创建场景，添加角色并编排对话片段，先用两个角色和少量轮次测试。
3. 无 Google TTS key 时，取消「语音」勾选；导出时选择不生成语音，仍可查看文字记录。
4. 「人工控制」需要角色被标记为人类参与者，并开启片段介入配置。它在候选介入时暂停审核，不会在每个普通 AI 发言前暂停。
5. 完成对话后导出，在「对话验证」中查看回放、图表和分析问答。

当前角色音色仍使用 Google 配置，中文语音效果取决于所选音色和服务支持。阿里百炼 TTS 尚未接入。部分额外口型生成接口依赖原项目的 Rhubarb/音频工具，仓库不包含对应平台的可执行文件；基础文字运行不依赖这些工具。

## 6. 关闭与重新启动

1. 在前端终端按 `Ctrl+C`。
2. 在后端终端按 `Ctrl+C`。
3. 关闭网页即可；网页关闭本身不会停止服务。

下次重复第 4 节即可，不必重新安装依赖、复制 `.env` 或清除浏览器数据。更新前端后刷新网页；更新后端后停止并重新启动后端。

## 7. 构建和测试

前端生产构建：

```powershell
cd client
npm run build
```

模拟回归测试（在仓库根目录执行）：

```powershell
cd server
npm test
```

此命令运行 `tests/*.test.js` 中的指定模拟测试，不需要真实 key，不产生模型调用费用；它不证明真实服务的账户权限、余额或网络可用。

## 8. 常见问题

| 现象 | 检查方法 |
|---|---|
| 保存密钥显示无法连接后端 / Failed to fetch | 确认后端终端仍在运行，且使用 localhost:5173 访问前端 |
| 端口被占用 | 先停止自己此前启动的服务；不要直接结束不认识的进程 |
| 模型返回 401/403 | 检查服务商选择、key 是否正确及账户权限 |
| 有文字但没有声音 | 检查是否勾选语音、Google TTS key、音色及服务网络 |
| 后端重启后提示未配置 | 检查 server/.env，或在网页重新保存密钥 |
| 新电脑没有此前的场景 | 场景及验证记录主要在原浏览器本地保存，不会通过 Git 自动同步 |

当前配置仅面向本机。GitHub 保存的是源代码，不会自动运行 Node.js 后端；直接启用 GitHub Pages 也不能替代后端服务。
